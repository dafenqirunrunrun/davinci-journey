# 76. 最小覆盖子串

> 今天只记录新学内容，不包含前面题目的复习内容。

- **难度**：困难
- **核心类型**：可变长度滑动窗口 + 哈希表
- **题目链接**：https://leetcode.cn/problems/minimum-window-substring/

## 1. 题目描述快照

> 下图是为了之后离线复习准备的“题目描述学习快照”，不用重新打开题目页也能快速想起题意。

![76. 最小覆盖子串｜题目描述快照](/assets/notes/76/01-76.webp)

### 题意重新说一遍

给定字符串 `s` 和 `t`，要在 `s` 中找到一段**最短的连续子串**，使这段子串能够满足 `t` 中每个字符的数量要求。

例如：

```text
s = "ADOBECODEBANC"
t = "ABC"
```

答案：

```text
"BANC"
```

因为 `BANC` 同时包含：

```text
A × 1
B × 1
C × 1
```

而且它是满足条件的最短连续窗口。

如果：

```text
t = "AABC"
```

那么窗口必须至少包含：

```text
A × 2
B × 1
C × 1
```

所以这题不仅看“有没有某个字符”，还要看**字符数量是否足够**。

---

## 2. 一句话核心思路

> **右指针不断扩张，直到窗口覆盖 `t`；一旦覆盖，就让左指针不断收缩，在所有合法窗口中寻找最短的那个。**

整个节奏：

```text
窗口不满足
    ↓
right 向右扩张
    ↓
窗口满足
    ↓
记录当前答案
    ↓
left 向右收缩
    ↓
直到窗口再次不满足
    ↓
right 继续扩张
```

记忆成：

> **不够就扩，够了就缩。**

---

## 3. 三个最重要的数据结构 / 变量

### 3.1 `need`：目标字符串需要什么

```python
need = {}

for c in t:
    need[c] = need.get(c, 0) + 1
```

例如：

```text
t = "AABC"
```

得到：

```python
need = {
    "A": 2,
    "B": 1,
    "C": 1
}
```

所以：

> `need` = **目标需求表**。

---

### 3.2 `window`：当前窗口里有什么

```python
window = {}
```

当右指针把字符放进窗口：

```python
window[c] = window.get(c, 0) + 1
```

例如当前窗口是：

```text
ADOBEC
```

只考虑 `t = "ABC"` 需要的字符时：

```python
window = {
    "A": 1,
    "B": 1,
    "C": 1
}
```

所以：

> `window` = **当前窗口状态表**。

---

### 3.3 `valid`：已经满足要求的字符种类数

这是整题最容易搞错的变量。

```python
valid = 0
```

它不是：

```text
窗口里已经有几个目标字符
```

而是：

> **有多少种字符已经达到 `need` 要求。**

例如：

```text
t = "AABC"
```

那么：

```python
need = {
    "A": 2,
    "B": 1,
    "C": 1
}
```

此时：

```python
len(need) == 3
```

因为一共只有三种字符：`A / B / C`。

如果当前窗口：

```text
AAB
```

那么：

```text
A：2 / 2 ✅
B：1 / 1 ✅
C：0 / 1 ❌
```

所以：

```python
valid = 2
```

当：

```python
valid == len(need)
```

才说明：

> **当前窗口已经完全覆盖 `t`。**

## 4. 标准代码

```python
class Solution:
    def minWindow(self, s: str, t: str) -> str:
        need = {}                       # t 中每个字符需要多少个
        window = {}                     # 当前窗口中字符出现多少个

        # 统计 t 的字符需求
        for c in t:
            need[c] = need.get(c, 0) + 1

        left = 0                        # 左指针
        right = 0                       # 右指针，窗口采用 [left, right)

        valid = 0                       # 已满足要求的字符种类数

        start = 0                       # 最优窗口的起点
        min_len = float("inf")          # 最优窗口长度

        while right < len(s):

            # -------------------------
            # ① 右指针扩张窗口
            # -------------------------
            c = s[right]
            right += 1

            # 只有 t 需要的字符才需要统计
            if c in need:
                window[c] = window.get(c, 0) + 1

                # 该字符数量第一次刚好达到需求
                if window[c] == need[c]:
                    valid += 1

            # -------------------------
            # ② 窗口已经合法，开始收缩
            # -------------------------
            while valid == len(need):

                # 先尝试更新最短答案
                if right - left < min_len:
                    start = left
                    min_len = right - left

                # ---------------------
                # ③ 左指针移出一个字符
                # ---------------------
                d = s[left]
                left += 1

                if d in need:
                    # 移出之前刚好满足需求，
                    # 那么移出后一定会变成不满足
                    if window[d] == need[d]:
                        valid -= 1

                    window[d] -= 1

        # 从来没有找到合法窗口
        if min_len == float("inf"):
            return ""

        return s[start:start + min_len]
```

## 5. 为什么右边加入字符时要判断 `==`？

关键代码：

```python
if window[c] == need[c]:
    valid += 1
```

例如：

```python
need["A"] = 1
```

第一次遇到 `A`：

```text
window["A"] = 1
```

刚好满足要求：

```python
valid += 1
```

如果后来又遇到一个 `A`：

```text
window["A"] = 2
```

此时不能再次：

```python
valid += 1
```

因为：

> `A` 这一种字符早已经满足要求了，多出来的 `A` 不代表多满足了一种字符。

所以只在：

```text
window[c] 从“不够”变成“刚刚够”
```

这一瞬间让：

```python
valid += 1
```

---

## 6. 为什么左边移出字符时要先判断，再 `-1`？

关键代码：

```python
if window[d] == need[d]:
    valid -= 1

window[d] -= 1
```

例如：

```python
need["A"] = 1
window["A"] = 1
```

当前 `A` 是刚好满足的。

现在左指针准备把它移出去。

移出以后：

```python
window["A"] = 0
```

就会从：

```text
满足 ✅
```

变成：

```text
不满足 ❌
```

所以要在删除之前判断：

```python
if window[d] == need[d]:
    valid -= 1
```

然后再真正减少窗口计数：

```python
window[d] -= 1
```

记忆：

> **进窗口：加完再判断。**  
> **出窗口：判断完再减。**

---

## 7. 为什么合法以后是 `while` 收缩，不是 `if`？

代码：

```python
while valid == len(need):
```

因为窗口一旦满足要求，我们的目标不是：

```text
“找到一个合法窗口就结束”
```

而是：

```text
“在合法的前提下尽可能短”
```

例如窗口：

```text
XXXXXXXXABC
```

已经覆盖 `ABC`。

显然要不断从左边删：

```text
XXXXXXXXABC
XXXXXXXABC
XXXXXXABC
...
ABC
```

只要删除以后仍然合法，就应该继续删除。

因此必须使用：

```python
while valid == len(need):
```

## 8. `[left, right)` 为什么很重要？

这份代码维护的是：

```text
[left, right)
```

也就是：

```text
left 包含
right 不包含
```

例如：

```text
s = "ABCDE"
left = 1
right = 4
```

窗口是：

```text
BCD
```

所以窗口长度直接是：

```python
right - left
```

即：

```text
4 - 1 = 3
```

因此更新答案：

```python
if right - left < min_len:
    start = left
    min_len = right - left
```

## 9. 示例执行：`ADOBECODEBANC`

```text
s = "ADOBECODEBANC"
t = "ABC"
```

需求：

```text
A × 1
B × 1
C × 1
```

### 第一次扩张

右指针不断移动：

```text
A
AD
ADO
ADOB
ADOBE
ADOBEC
```

到了：

```text
ADOBEC
```

此时：

```text
A ✅
B ✅
C ✅
```

所以窗口合法。

记录：

```text
当前最短 = "ADOBEC"
长度 = 6
```

然后开始移动 `left`。

移走 `A` 后：

```text
DOBEC
```

变成：

```text
A ❌
B ✅
C ✅
```

窗口失效，于是停止收缩，继续扩张 `right`。

经过后续扩张和收缩，最终得到：

```text
BANC
```

长度：

```text
4
```

## 10. 滑动窗口通用骨架

这部分值得直接背。

```python
left = 0
right = 0

while right < len(s):

    # 1. 右边字符进入窗口
    c = s[right]
    right += 1

    # 2. 更新窗口状态
    ...

    # 3. 当前窗口满足条件后，尝试收缩
    while 窗口满足条件:

        # 4. 更新答案
        ...

        # 5. 左边字符离开窗口
        d = s[left]
        left += 1

        # 6. 更新窗口状态
        ...
```

这题只是在模板里加入：

```text
need
window
valid
```

来判断：

```text
当前窗口有没有覆盖 t
```

## 11. 最容易写错的地方

### 错误 1：把 `valid` 当成字符总数

错误理解：

```text
valid = 窗口里已经包含多少个目标字符
```

正确：

```text
valid = 已经满足需求的字符种类数
```

---

### 错误 2：使用 `valid == len(t)`

错误：

```python
while valid == len(t):
```

正确：

```python
while valid == len(need):
```

因为 `valid` 数的是字符**种类**。

---

### 错误 3：忘记字符可能重复

例如：

```text
t = "AABC"
```

不是只需要：

```text
A、B、C
```

而是需要：

```text
A × 2
B × 1
C × 1
```

因此不能只用 `set(t)` 判断。

---

### 错误 4：合法后只收缩一次

错误：

```python
if valid == len(need):
```

正确：

```python
while valid == len(need):
```

因为要一直缩到窗口刚好失效，才能逼近最短答案。

---

### 错误 5：忘记处理无解情况

初始化：

```python
min_len = float("inf")
```

最后：

```python
if min_len == float("inf"):
    return ""
```

## 12. 时间复杂度

构建 `need`：

```text
O(|t|)
```

滑动窗口：

```text
O(|s|)
```

虽然代码里出现：

```python
while right < len(s):
    while valid == len(need):
```

看起来像两层循环，但：

```text
right 只从左向右走一遍
left 也只从左向右走一遍
```

每个字符最多：

```text
进入窗口一次
离开窗口一次
```

所以总时间复杂度：

```text
O(|s| + |t|)
```

空间复杂度：

```text
O(|字符集|)
```

如果只考虑英语字母，可以看成常数级额外空间；更一般地，也可以写成 `O(|Σ|)`。

## 13. 面试口述版

> 我会使用可变长度滑动窗口。首先用 `need` 统计目标字符串 `t` 中每个字符需要的数量，再用 `window` 维护当前窗口内目标字符的数量，并使用 `valid` 记录已经满足要求的字符种类数。右指针持续扩张窗口，当 `valid == len(need)` 时说明窗口已经覆盖 `t`，此时不断移动左指针收缩窗口，并在收缩过程中更新最短答案。由于左右指针都只会单调向右移动一次，因此整体时间复杂度是 `O(|s| + |t|)`。

## 14. 今天的最短记忆版

### 核心口诀

> **need 记需求，window 记窗口；右边进，满足就缩；缩之前记答案，缩到不满足再继续扩。**

再压缩：

> **不够就扩，够了就缩。**

### 三个变量

```text
need   → t 需要什么
window → 当前窗口有什么
valid  → 有多少种字符已经满足需求
```

### 三个最关键判断

```python
if window[c] == need[c]:
    valid += 1
```

```python
while valid == len(need):
```

```python
if window[d] == need[d]:
    valid -= 1
```

### 最终模板印象

```text
右边进
  ↓
更新 window / valid
  ↓
窗口合法？
  ↓ 是
记录答案
  ↓
左边出
  ↓
更新 window / valid
  ↓
失效后继续扩张
```
